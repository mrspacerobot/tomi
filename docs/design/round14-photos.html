Comment 9: where the dish photos could come from

Four sources, and what each costs

SourceGoodWatch out
Made by an image model, per recipe (my pick)Every recipe in the server's graph gets one, in one consistent style. It can be made for each version of a dish, so the olive-oil version shows olive oil. Made once on the server when a recipe is added, then kept.A person checks each one before it goes live, so a photo never shows food the recipe does not have. Costs a little per image.
Your own photo at the end of a cookFree, real and personal. It fills your own cookbook (screen 9C), and gives the wrap a moment to feel proud.Only exists after you cook, so it cannot sell tonight's dish. More photos kept, so it waits for the consent step before anyone outside TestFlight.
Our own photographyThe best looking, and exactly our dishes.Slow and costly for every recipe and every version.
Stock photo librariesCheap, many to choose from.Rarely the exact dish. Licences vary, some need credits like the ones below.

Either way the app holds no images: the server sends a photo address with each suggestion, and the app shows Tomi's drawing if the photo cannot load. AGENTS.md says pictures are drawn in code, so adding photos means changing that rule in the same pull request.

For comment 8 the app already has your photo, because you just took it. The server only needs to send back where each item sits in the photo, as a box or a point, next to each name it already sends.
